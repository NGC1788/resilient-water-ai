# 계산 모델 (v0.2)

## 변수

- 1단계(모든 시나리오 공통): 투자 이진변수 `y[a]`. 그리고 재난 인지 전 `t < P`(P = `prep_days`)일의 모든 운영변수. 비예견성 행 `v[s,t] = v[s0,t]`(t < P)로 시나리오 사이에 같게 묶는다.
- 2단계(시나리오 s별): `t ≥ P`일의 취수 q, 링크 흐름 f, 공급 x, 전체 부족 u, 필수 부족 h, 배수지 저장 S.
- 시나리오 조건(수율·수요 배수, 고장 링크·수원, 링크별 용량 배수)은 `t ≥ P`일에만 적용한다. `t < P`일은 정상 조건이다.

## 제약

- CAPEX = Σ cost[a] y[a] ≤ B. enabled=false, DENIED, 삭제 실험 후보는 y=0. 배타 옵션은 Σy ≤ 1.
- 후보 f ≤ cap·y, 기존 f ≤ cap. 고장 링크 f = 0. 처리 링크는 정수장 처리 한계 이하. `capacity_factors`로 링크별 용량 배수를 줄 수 있다(예: 수위 저하로 중력 유량 감소).
- 수원 q ≤ yield·factor (고장 수원은 0).
- 일반 노드: 유입 − 유출 = 0. 수원: 유입 + q − 유출 = 0.
- 수요: 유입 − x = 0, x + u = demand, x + h ≥ essential, 0 ≤ x ≤ demand.
- 배수지: S[t] = S[t−1] + 유입 − 유출, Smin ≤ S ≤ Smax. 초기 저장량은 노드 값이다. 시나리오별 `initial_storage`는 `prep_days = 0`일 때만 허용한다(사전 공통 기간은 하나의 상태를 공유해야 하므로).
- 원수→정수 변환은 처리 링크에서만. 처리 수율 1의 단순화.

## 사전식 목적

| 순서 | 목적 | 비고 |
|---|---|---|
| 0 | Σ(t<P) u 최소화 | 재난 인지 전 정상 공급 우선. `allow_prep_rationing=True`면 생략(사전 제한급수 허용) |
| 1 | max_s Σ(t,i) h | 최악 시나리오 필수 부족 |
| 2 | max_s Σ(t,i) u | 최악 시나리오 전체 부족 |
| 3 | max_(s,r) Σ(t,i∈r) u / Σ(t,i∈r) demand | **최악 지역 부족률(형평성)** |
| 4 | Σ(s,t,i) h | |
| 5 | Σ(s,t,i) u | |
| 6 | Σ cost·y / 1억 | 투자비 |
| 7 | −Σ(s, 배수지) S[마지막 날] | **남는 물 최대화**: 필요 없는 저장량 소진 방지 |

### 수치 처리

- 앞 단계 최적값 고정: `값 + max(1e-6, 1e-7·|값|)`. v0.1의 절대 1e-6은 14일 이상에서 솔버 허용오차보다 작아져 "infeasible"로 실패했다.
- 설계 다듬기: MILP로 고른 y를 정확히 고정하고 같은 단계를 LP로 다시 푼다. MIP 정수 허용오차(y≈1e-6 × 링크 용량) 때문에 선정되지 않은 링크로 물이 새는 것을 막는다.
- 2×10⁻⁶ 미만의 잔여값은 0으로 정리한다. 독립 검증의 물량 보존 허용오차는 1e-4다.
- 솔버가 최적성을 증명하지 못하면 `SolverFailure`, 불능이면 `InfeasibleModel`을 낸다. 실패를 성공으로 바꾸거나 "대안 없음"으로 둔갑시키지 않는다.

## 대안과 설명

- 상위 대안: 앞서 나온 투자 조합을 no-good cut으로 배제하고 다시 푼다. 앞선 대안보다 모든 성능 지표(1~5번)가 같거나 나쁘고 투자비도 같거나 큰 조합은 **열등안**으로 따로 기록하고 대안에서 뺀다(최대 9회 풀이).
- 반사실적 설명: 선정 후보 하나를 금지하고 나머지 투자·운영을 같은 예산·시나리오로 다시 최적화한다.
- 운영 재최적화: 선정 망과 이미 실행한 재난 전 운영을 고정하고 재난 기간만 다시 푼다.
- 재난 인지 후 남은 기간은 완전정보로 푼다. 매일 다시 계산하는 MPC는 아직 없다.

## 정책 비교

`policies.py` 머리말 참고. A는 하루 단위 max-min 공정 비례 배분(물 채우기 방식)과 평상 수위 유지, B·C는 재난 전 운영만 다르고 재난 후 재최적화는 같다. 모든 정책을 같은 개발·held-out 시나리오와 같은 지표로 평가한다. 확률이나 기대값은 쓰지 않는다.
