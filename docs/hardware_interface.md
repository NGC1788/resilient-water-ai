# 하드웨어 축소모형 연동

## 모형

팀 하드웨어 설계(중력식 탁상 모형)를 `data/hardware/gravity_twin_network.json`으로 옮겼다.

```
 [수원 A 페트병] ══ 연결관 V4(집게) ══ [수원 B 페트병]
   │ R1      │ R3A               R3B │      R2 │      ← 서보가 호스 끝 높이로 조절
   ▼         └──────▶ 병원(필수) ◀──────┘        ▼
 주거1 컵                                     주거2 컵   ← 힘센서로 무게 측정
```

| 항목 | 값 | 근거 |
|---|---|---|
| 단위 | mL / 주기(60초) | 하드웨어 계획 1일 = 60초 |
| 수원 A·B | 초기 1500, 최소 200, 최대 1800 mL | 2 L 페트병, 최소 200 mL는 수두 유지용 |
| 수요 | 주거1 150(필수 50), 병원 120(전부 필수), 주거2 130(필수 50) mL/주기 | 가정값 |
| 라인 용량 | 300 mL/주기 | **보정 전 가정**(5 mL/s × 60 s). 서보 각도→유량 보정표로 바꿔야 함 |
| 연결관 A↔B | 200 mL/주기, 양방향 | 중력 연통관이라 실제로는 제어 불가(집게 개폐만) |

시나리오(`gravity_twin_scenarios.json`)는 하드웨어 계획과 같다. NORMAL, DROUGHT(A를 1/3만 채움 + A 라인 0.6배), PIPE_BREAK(A→병원 집게), COMPOUND, held-out SUPPLY_STOP_A(원래 '정전'을 펌프가 없어 대체).

## 흐름

1. 앱에서 데이터 "하드웨어 축소모형" → 설계 실행 → "하드웨어 모형 연동" 화면.
2. 정책·시나리오를 고르면 주기별·라인별 목표량 표가 나온다. JSONL로 내려받는다.
   ```json
   {"type":"line_target","seq":0,"plan_id":"PLAN-…-C_ROBUST-NORMAL","cycle":0,"line":"R1","edge_id":"A-R1","target_ml":150.0,"requires_approval":true}
   ```
   연결관처럼 서보 라인이 없는 링크에 유량이 있으면 `"type":"manual_link"`로 표시한다(사람이 집게로 처리하거나 계획을 바꿔야 함).
3. 하드웨어 PC 제어기가 운영자 승인 후 실행한다. 서보 열기/닫기와 무게 판단은 제어기 몫이다(HARDWARE_HANDOFF §6의 open/close/hb 규격).
4. 측정 결과 CSV를 앱에 올리면 계획 대비 오차를 계산한다.
   ```csv
   cycle,node_id,measured_ml
   0,R1,142.5
   0,H,120.3
   ```

## 안전 경계

- 이 소프트웨어는 직렬 포트를 열지 않고 장치에 명령을 보내지 않는다.
- 모든 목표 행은 `requires_approval: true`다.
- 비상정지·통신 끊김 정지(2초)·고무줄 닫힘은 펌웨어와 물리 장치에서 독립적으로 동작해야 한다.

## 보정 후 바꿀 것

- 라인별 `capacity`를 보정표의 최대 유량 × 60초로 바꾼다.
- 가뭄 시 수위가 낮아 줄어드는 유량을 측정해서 `capacity_factors` 값으로 넣는다.
- 축소모형 결과는 탁상 모형에 한정된다. 실제 관망과는 축척·수리 특성이 다르다.
