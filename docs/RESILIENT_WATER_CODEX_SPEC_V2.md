# RESILIENT-WATER AI — Codex 구현 지시서 v2

> **최우선 요구사항**: 재난 시나리오가 발생하기 **전에** 국가·광역·지역 간 물 이송·공급망의 후보 연결 및 비상 공급 계획을 설계하고, **왜 그 대안을 선택했는지** 검증 가능한 수치와 반사실적 비교로 설명하는 소프트웨어를 구현하라. 단순 위험도 대시보드나 기존 관망의 실시간 배분 최적화만 만들면 요구사항 미충족이다.

## 0. 작업 지시 / 범위

- Python 기반 실행 가능한 **의사결정 지원 시스템(Decision Support System)**을 실제 코드로 구현한다. 한국어 UI. 임의 수치로 그럴듯한 결과를 출력하지 않는다.
- **사전 설계(Planning)**와 **재난 후 운영(Operation)**을 구분한다. 사전 설계는 신규 연결 관로·우회 송수로·추가 저장/펌프 설비 등 투자 대안을 산출하며, 사후 운영은 이미 건설된 망을 대상으로 시나리오별 취수·송수·배분 계획을 산출한다.
- 국가 전체는 향후 데이터 확보 시 적용할 **확장 가능한 계층적 모델**로 설계한다. MVP는 2~3개 유역/급수권역, 3~5개 공급원, 5~8개 수요 지역, 기존 링크 및 후보 신설 링크가 포함된 **명확히 가상인 데이터**로 동작하게 한다. 실제 전국 수로망을 설계·검증했다고 주장하지 않는다.
- '수로'는 구체적으로 원수의 광역 도수/송수, 정수처리 후 급수용 연결관을 **서로 다른 네트워크 계층**으로 구분한다. 하천·운하·댐·정수장·상수관을 모두 동일한 관로로 계산하지 말 것.
- 이 결과는 건설 허가·환경영향평가·수리권 검토·현장 측량·상세 설계를 대체하지 않는다. 실제 위치·공사비·허용 취수량이 없으면 **개념 설계**로 표시하고 승인·시공용이라는 표현을 금한다.
- **피지컬 컴퓨팅 실제 연결은 이번 단계에서 구현하지 않는다.** 향후 센서/펌프/밸브 연결을 위한 DTO/API 인터페이스만 준비한다.

## 1. 사용자에게 제공해야 하는 최종 산출물

각 시나리오 또는 시나리오 묶음에 대해 아래 내용이 들어 있는 **사전 대비 계획서(Preparedness Plan)**를 자동 생성한다.

1. **설계도**: 기존 공급망(실선) + 제안하는 신규/증설/우회 링크(점선) + 공급원·정수장·배수지·수요지역·펌프장 노드 및 구분된 물 유형(원수/정수)의 지도/그래프.
2. **건설·확충 권고 목록**: `asset_id`, 자산 종류, 시작/끝 노드, 후보 노선, 설계 용량, 비용 추정, 고도 차, 시공/법제 제약, 선정 여부, 불확실성, 설계 상태.
3. **운영 시나리오별 계획**: 재난 발생 시 사용할 공급원, 시설별 처리/공급량, 각 구역 공급량·미충족 수요, 저장량 변화, 우회 경로, 전환 조건, 복구 조치.
4. **타당성 검증**: 흐름 보존, 취수/수원 제약, 정수 능력, 관로 공급량, 비상 저장량; 가능한 경우 EPANET/WNTR의 유량·압력 검증 결과. 통과하지 못한 설계는 `NOT_VALIDATED`/`INFEASIBLE` 처리.
5. **설계 선정 이유(필수)**: 대안별 비용/피해 감소/시나리오 커버리지, 가장 큰 병목, 중요한 제약, 선택하지 않은 상위 대안과 비교, 해당 연결을 제외했을 때의 결과(반사실적 비교), 결과가 달라지는 조건, 입력 자료·가정·품질·분석 버전.
6. **단계별 투자·준비 로드맵**: 비상운영 매뉴얼 → 기존 시설 운영 변경 → 소규모 증설 → 광역 신규 연결의 단계, 선행 조건과 우선순위.
7. **보고서**: 화면 표시 및 JSON/CSV/GeoJSON/HTML, 가능한 경우 PDF 내보내기. 결과가 재현될 수 있도록 입력 해시, 시나리오 버전, 코드 버전, solver 상태를 포함한다.

## 2. 서비스 핵심 사용자 흐름

```text
[데이터 카탈로그/관망 입력]
         ↓
[품질 검사 → 원본 보존/오류 격리 → 단위/좌표계/시설 연결 표준화]
         ↓
[공급망 디지털 그래프 생성: 수원/취수/처리/송수/배수/수요]
         ↓
[지역 위험도·취약성 분석 및 위험 권역 선택]
         ↓
[재난 시나리오 생성: 가뭄/관로 파손/펌프 장애/복합 + 미관측 극단]
         ↓
[후보 인프라 생성: 기존 관로 증설/신규 연결/우회로/저장시설/펌프/대체수원]
         ↓
[★ 사전망 설계 최적화: 제한된 투자 예산 하 시나리오 피해 최소화]
         ↓
[★ 선택된 망에서 재난별 운영·물 배분 계획 계산]
         ↓
[유량/압력 검증, 불가능하면 후보 수정·재최적화]
         ↓
[★ 지도 위 사전 설계안 + 정량적 선정 이유 + 반사실적 비교]
         ↓
[준비 매뉴얼/공사 후보 리스트/투자 우선순위 및 대응 계획서 내보내기]
```

**사용자 동작:** (1) 권역과 재난 유형 선택 → (2) 예산·계획기간·보호대상 설정 → (3) '사전 대비망 설계' 실행 → (4) 상위 3개 설계 대안과 비용·복원력 비교 → (5) 링크 선택 후 '왜 선택했나/왜 제외했나' 열람 → (6) 시나리오 실행/검증 → (7) 대비 계획서 내보내기.

## 3. 물리적 공급망 모델: 국가 규모로 확장 가능한 층위

1. **수원 층**: 댐·저수지·하천 취수점·비상 지하수·대체 수원. 저수량/유입량/최소 유지량/허용 취수량/수리권/용도 제한.
2. **원수 이송 층**: 취수시설 → 도수/광역 원수 이송로 → 정수장. 유량·고도·펌프·처리 가능 원수 조건.
3. **정수 층**: 정수장 처리량·원수 및 처리수 적합성. 원수와 정수는 무제약 교환 금지.
4. **정수 송·배수 층**: 정수장→배수지→급수권역; 관경·길이·거칠기·고도·펌프·밸브·압력.
5. **수요 층**: 생활/병원/산업/농업 등의 수요 및 필수 최소량. 농업용수 망은 음용 수도망과 물리·수질상 분리 모델로 처리.
6. **권역 간 연계**: 유역 간/급수권역 간 이동은 `interbasin_transfer` 후보 링크로 정의. 국가 차원의 법적·환경적·사업 타당성 검토 필요 표기.

**핵심 주의**: 그래프상 최단 경로가 실제 물의 흐름 경로는 아니다. 그래프 흐름은 계획용 근사이며, 압력 관망은 EPANET/WNTR로 검증한다. 개방 수로/하천의 수리학을 EPANET 압력관 모형으로 검증한 것처럼 표시하지 말라. 미지원 네트워크 층은 `CONCEPTUAL_ONLY`로 표시하라.

### 3.1 시설·링크 스키마

- `node`: `node_id`, `name`, `type`, `water_type`, `region_id`, `basin_id`, `x`, `y`, `crs`, `elevation_m`, `existing`, `storage_m3`, `storage_min_m3`, `source_yield_m3_day`, `treatment_capacity_m3_day`, `demand_m3_day`, `essential_demand_m3_day`, `data_source_id`.
- `edge`: `edge_id`, `from_node`, `to_node`, `layer`, `water_type`, `existing`, `status`, `capacity_m3_day`, `length_m`, `diameter_mm`, `roughness`, `headloss_model`, `pump_curve_id`, `availability`, `cost_opex_per_m3`, `provenance`.
- `candidate_asset`: `candidate_id`, `asset_type`(`new_pipe`,`upgrade_pipe`,`new_pump`,`storage_expansion`,`new_interconnection`), `from_node`, `to_node`, `layer`, `water_type`, `route_geometry`, `route_source`, `proposed_capacity_m3_day`, `capex_estimate`, `capex_uncertainty`, `opex_estimate`, `lead_time_months`, `environmental_status`, `permit_status`, `feasibility_flags`, `validity_level`.
- `node`와 `edge` ID 중복을 검출하고, 시설 유형에 맞지 않는 연결/원수-정수 혼합을 금지한다.
- 좌표·경로 정보가 없을 때는 논리적 네트워크 시각화만 제공하고 **실제 지도상의 신설 노선**처럼 보여주지 않는다.

## 4. 데이터/FAIR/품질 관리

### 4.1 데이터 카탈로그

`dataset_id`, 명칭, 기관, 원문 URL, 라이선스, 갱신주기, 관측/공간 단위, CRS, 스키마·단위, 마지막 수집일/관측일, 품질 점수, 변경 이력, 원본 해시, 사용한 모델/계획서 ID를 저장한다. 원본 보존, 정제 데이터 버전 관리, 데이터 계보(lineage), 검색과 내보내기를 제공한다.

### 4.2 서로 다른 공간 단위 연결

행정구역↔기상관측소, 유역↔수원, 취수원↔정수장, 수원↔급수권역, 배수지↔수요지역, 농업용수권역↔농경지의 `spatial_links` 테이블. `source_id`, `target_id`, `relation`, `weight`, `method`, `source`, `confidence`, `valid_from`, `valid_to`, `review_status` 포함. **지도상 인접성만으로 수도 공급 가능 연결을 추정하지 말 것.**

### 4.3 과거 대응 이력/사후평가

제한급수, 운반급수, 비상관정, 대체수원 연계, 임시 송수, 복구/펌프 운전 변경에 대해 대상, 시점, 비용, 성과, 실패 사유, 출처를 기록하고 유사 상황 검색을 제공한다. 과거 사례는 **후보 제안과 교차검증**에 사용하되 미관측 재난의 가능성을 억제하거나 과거 조치의 인과적 효과를 증명했다고 주장하지 않는다.

### 4.4 데이터 오류 정책(필수 테스트 포함)

- **0은 반드시 무효가 아님**: 무강수 0mm, 차단된 관로의 유량 0은 정상. 음수 강수·음수 저장량·관경 0 이하는 오류.
- 의심 데이터는 곧바로 영구 삭제하지 않는다. 원본 보존 → 규칙 검사 → `PASS`, `FLAGGED`, `QUARANTINED`, `IMPUTED` 라벨 → 분석 입력에서 부적합 행 제외 → 이력 기록.
- 센서 0 고착, 단위 불일치, 중복 관측, 시간 역전, 자료 갱신 지연, 지리좌표 오류 탐지.
- 극단적인 실제 재난 관측값은 임의 이상치 제거로 학습에서 삭제하지 않는다.
- 분석 결과에서 사용된 결측치 보정과 자료 부족 경고 표시.

## 5. 위험 분석과 시나리오 생성

- 위험 점수는 `노출도`, `물 부족 취약성`, `필수시설 피해 규모`, `대체 공급 능력`, `복구 역량`의 구성값을 공개한다. **0~100 점수 ≠ 발생 확률**.
- AI는 관측과 수요/유입량의 *조건부 범위* 및 위험 인자 분석에 사용할 수 있다. 신뢰 가능한 사건 레이블이 충분하지 않으면 규칙 기반 모델을 우선한다.
- 시나리오 생성: `NORMAL`, `LONG_DROUGHT`, `EXTREME_DROUGHT`, `HEAT_DEMAND_SURGE`, `PIPE_BREAK`, `PUMP_OUTAGE`, `SOURCE_CONTAMINATION`, `COMPOUND`.
- 시나리오 입력: 기간, 유입 감소/수요 증가 범위, 고장 노드/링크, 유지 저수량, 복구 지연, 선택적으로 주관적 확률/가중치(근거/검증 없으면 **확률로 명명 금지**).
- 관측되지 않았던 극단 조합 생성과, 개발에 사용하지 않은 별도 검증 시나리오 포함.
- 확률이 정당화되지 않을 경우 **최악 시나리오 기준 강건 최적화**로 처리하고, 확률 기반 기대값을 무리하게 계산하지 않는다.

## 6. ★ 핵심 차별점: 사전 '공급망 설계'와 시나리오별 '배분'의 결합

### 6.1 두 시간축의 의사결정

**Stage 1 — 재난 전 사전 투자/설계**: `y_a∈{0,1}` 후보 신규 링크·펌프·저장 용량의 채택 여부, 옵션별 설계용량 `u_a`, 예산 `B`, 공사기간과 허가 제약. 건설 후 모든 재난 시나리오에서 공통으로 이용할 **하나의 설계망**을 결정한다.

**Stage 2 — 시나리오 발생 후 운영**: 각 시나리오 `s`, 시간 `t`에 대해 공급원별 취수량 `q_source[s,t]`, 링크 유량 `f_edge[s,t]`, 배수지 저장량 `S[s,t]`, 지역별 공급량 `x_region[s,t]`, 필수 수요 부족량 `shortfall_essential[s,t]`을 결정한다. 재난 전에는 실제 발생 시나리오를 알 수 없다는 **비예견성(non-anticipativity)** 원칙을 준수한다.

### 6.2 필수 수학 요구사항

개념 목적함수(가중치와 단위는 정규화 후 사용):

`min_(design y, operations x_s) [ CAPEX(y) + λ * max_{s in S} Damage(y, x_s, s) + μ * OPEX(y, x_s) ]`

또는 **예산 제약** `CAPEX(y) ≤ B` 하에 `max_s Damage`를 최소화한다. 두 방식 중 하나를 기본으로 구현하되 사용자에게 선택 옵션 제공 가능.

- 필수 수요 부족량에 가장 높은 우선순위(가급적 사전식 목표).
- 각 노드의 질량보존, 공급원별 기간 물수지, 최소 저장량, 취수·처리·송수 용량, 시설 상태 제약 반영.
- 후보 링크 용량은 **선정한 경우에만** 열림: `0 ≤ f_candidate[s,t] ≤ y_a * capacity_a` (유량 방향을 물리 조건에 맞게 취급).
- `CAPEX = Σ asset_cost_a*y_a`; 서로 배타적인 사업 옵션, 예산, 허가/환경/수질 부적합 후보는 선택 금지.
- 수요를 넘는 공급으로 성능을 부풀릴 수 없도록 `0 ≤ supply_i ≤ demand_i`.
- `required_min_essential_i` 미충족 시 조작된 feasible 결과가 아니라 **필수 부족량**을 계상.
- 국가·권역 간 연계는 유역/수질/허가 문제를 단순 관로 한 개로 해결했다고 간주하지 않는다.
- 초기 MVP는 **선형 네트워크 용량 및 저장량 근사 MILP**로 후보 망과 배분계획을 산출하고, 압력관망이 있는 부분을 WNTR/EPANET로 후속 검증한다.
- 물리적 모델 수준을 결과에 `GRAPH_FEASIBLE`, `HYDRAULIC_VALIDATED`, `CONCEPTUAL_ONLY`, `INFEASIBLE`로 명시.

### 6.3 후보 노선 생성

1. 기존 노선 증설, 끊어진 권역 간 연결, 비상 우회 관로, 펌프 보강, 저수/배수 저장 증설, 대체 수원 옵션을 생성.
2. 사용자가 직접 후보를 추가·비활성화·설계 용량을 지정할 수 있다.
3. 지도 기반 후보 경로는 검증된 GIS 도로/지형/보호구역과 근거가 있을 때만 제안하며, 없으면 **노드 간 추상 후보 링크**로 처리한다.
4. 공사비는 단가 가정/거리/지형 난이도를 이용한 **예시 추정치**로 표시하고 산식과 단가 출처를 공개. 수치 출처가 없으면 입력받거나 synthetic이라고 표시한다.
5. 허가나 실제 건설 가능성이 확인되지 않은 옵션은 `PRELIMINARY_CANDIDATE`로 표시한다.

### 6.4 사전 대비 계획 라이브러리

각 시나리오에 대해 단일 대응안을 저장하는 것을 넘어 **여러 시나리오에서 공통으로 유용한 사전 설계망**과 그 망을 이용한 **상황별 운영 매뉴얼**을 묶어 저장한다.

- `design_portfolio`: 설계망 ID, 예산, 후보 설비 리스트, 적용 시나리오, 설계 버전.
- `response_playbook`: `trigger` (저수율/유입량/펌프장 장애 등), 전제 조건, 허용 시설, 취수·배분 계획, 필수시설 보호, 인적 승인 필요 여부, 대체 플랜.
- 미리 계산한 계획을 저장하지만 실제 재난 시 실측 정보를 사용해 **재최적화**한다. 저장된 유량을 그대로 물리 시설로 전송하지 않는다.

## 7. ★ 결과의 설명 가능성 — 필수 및 독립 기능

LLM으로 일반적인 설명 문구를 생성하는 것이 아니라 **최적화 기록과 반사실적 재계산으로 근거를 확보**하라.

모든 추천 자산 및 배분 계획에 대해 아래 스키마를 생성한다.


### 7.1 필수 설명 화면

- **선택 이유:** 어떤 구역의 필수 공급 부족이 얼마나 줄었는가? 최악 재난 피해를 얼마나 줄였는가? 비용 대비 효과는?
- **대안 비교:** 비용이 더 저렴한 경로가 왜 제외되었는가? 고장 시 취약해서인가, 공급 압력/처리량 제약 때문인가?
- **반사실적 비교:** 신규 링크 하나를 계획에서 제외한 후 나머지를 동일한 조건에서 재최적화해 피해/비용 변화를 제시.
- **제약 설명:** 병목 링크, 공급원 부족, 정수시설 한계, 예산 상한, 불허된 노선 표시.
- **불확실성:** 데이터를 바꾸거나 더 심한 재난을 가정할 때 계획의 순위가 뒤집히는지 민감도 분석.
- **검증 수준/출처:** 실제 관측인지 synthetic인지, 수리학 검증 여부, 미확정 허가/비용, 시나리오/알고리즘 버전.
- **설명 불가능:** 알고리즘이 충분한 원인 정보를 제공하지 못하면 추측하지 말고 `EXPLANATION_UNAVAILABLE`로 표시.

### 7.2 보고서 문장 생성 규칙

한국어 템플릿을 우선 사용하고 숫자는 엔진에서 가져온다. 예:

> “복합 재난 시나리오에서 기존 망의 최악 필수 수요 부족량은 [계산값]m³/일이다. 신규 [후보 링크]를 포함한 설계에서는 [계산값]m³/일로 감소했다. 해당 후보를 제외하고 재최적화했을 때 [계산값]m³/일로 악화되어, 이 후보는 특정 지역의 연결망 단절 위험을 줄이는 데 기여한다. 다만 본 노선은 [검증 수준]이며 실제 인허가·환경·수리학 상세 검토가 필요하다.”

설명에 사용된 모든 수치는 결과 테이블의 특정 열/실행 ID로 역추적 가능해야 한다.

## 8. 프론트엔드 화면(최소 9개)

1. **전국/권역 개요**: 국가→유역→급수권역→시설의 계층 탐색; 실제 공간 데이터 없는 경우 가상 데모 표식.
2. **데이터 카탈로그와 품질**: 출처·라이선스·오류 격리·공간 매핑·전처리 계보.
3. **현재 공급망**: 원수/정수 레이어 토글, 노드/기존 링크, 공급능력 및 병목.
4. **위험 지역 분석**: 물 부족/대체망 취약성, 위험 점수 구성 및 설명.
5. **재난 시나리오 제작실**: 유입량, 수요, 고장, 기간, 복합 재난 설정, 미관측 스트레스 테스트.
6. **★ 사전 대비망 설계 스튜디오**: 예산 슬라이더, 후보 신규 노선·저장시설·펌프 선택, 공통 망 설계 최적화, 상위 3개 대안 비교.
7. **★ 선정 이유 및 대안 비교**: 각 선정 자산의 편익, 비용, 병목, 삭제 실험, 제약/민감도, 검증 상태.
8. **재난 대응 운영 시뮬레이터**: 특정 설계망·시나리오에 따른 취수/송수/지역 공급량·필수 부족량과 대응 트리거.
9. **★ 대비 계획서 / 사업 우선순위 출력**: 지도, 후보별 공사·운영 권고, 단계별 로드맵, 설명, 검증 결과를 다운로드.
10. **대응 이력**(가능하면): 과거 제한급수·운반급수 등과 사후평가 탐색.

데모 결과 숫자나 지도 위 신규 노선은 계산과 데이터를 기반으로 표현한다. 설명 없는 임의 선 그리기나 미리 계산한 상수 출력은 금지한다.

## 10. 개발 단계 및 완료 기준

### P0: 가장 중요한 작동 MVP — **우선 완성**

- 2~3개 공급권역이 존재하는 가상 수원·정수·배수·수요 그래프, 기존 연결 및 **신규 후보 링크 4개 이상**.
- 정상/가뭄/관로 고장/복합 재난 포함 4개 이상 시나리오.
- 현행 망(투자 0)과 사전 신설/증설 투자를 비교하는 **다중 시나리오 시설 선택 MILP**.
- **시나리오별 운영 계획 + 최악 부족량 + 필수 수요 부족량** 출력.
- 지도/그래프에서 신규 후보를 실제 선택 여부에 따라 구분.
- **선정한 링크를 제외하고 다시 풀어 보는 반사실적 설명**.
- 대안 3개 이상을 만들거나 충분한 대안이 없을 시 이유를 명확히 표시.
- 결과 보고서(HTML/JSON/CSV) 내보내기.
- 자동화 테스트 + 한 번의 실행 명령 + README.

### P1: 데이터 계층 고도화

- FAIR 카탈로그, 공간 단위 연결, CSV/GeoJSON/EPANET 파일 수입, 원본/정제 데이터 분리, 이상치 격리와 품질 근거.
- 실제 공개 데이터 연결은 출처/이용 조건 확인 후 확장.

### P2: 수리 검증 및 개선

- 정수 배수망 부분에 WNTR/EPANET 연결 및 PDD 압력 검증.
- 수리 검증 실패 시 원인 표시/후보 변경 후 재최적화, 실제 압력관이 아닌 구간은 개념 단계 표시.

### P3: 설명과 국가 확장 고도화

- 투자/시나리오 민감도 그래프, 다수 권역 데이터 로딩, 과거 대응 사례 검색, 단계별 건설/운영 계획 및 권역별 권한 관리.

### P4: 하드웨어 인터페이스(이번 요청에서 보류)

- `TelemetryDTO`, `ProposedControlDTO`와 안전 인터록 개념만 문서화. 실제 센서/펌프 제어 코드는 작성하지 않는다.

## 11. 자동 테스트 (반드시 실행)

1. `0 mm` 강수는 보존, 음수 강수는 격리, 원본 불변.
2. 원수 링크에서 처리 없이 정수 수요 노드로 직접 공급하지 못함.
3. 기존에 끊어진 두 권역이 후보 링크 선정 전에는 연결되지 않고, 선정 후에만 흐름 허용.
4. 예산 부족 시 신규 링크가 선정되지 않거나 실행 불가로 표시.
5. 선택한 후보의 비용 총합은 예산을 초과하지 않음.
6. 모든 시나리오에서 네트워크 흐름 보존, 용량·저수량 제약 유지.
7. 극단 가뭄에서 모든 필수 수요를 충족하지 못하면 부족량을 정확히 출력.
8. 후보 자산을 제외한 반사실적 재최적화 결과가 실제로 다시 계산되어 재현됨.
9. 설명 문구의 숫자는 해당 `run_id` 출력과 정확히 일치.
10. 원자료 없는 국가 지도·관로 노선을 실재 인프라로 표시하지 않음.
11. 유압 수리 검증을 수행하지 않은 그래프 결과는 `HYDRAULIC_VALIDATED`가 아님.
12. 시나리오를 하나만 바꿔도 계산이 다시 실행되고, 무관한 고정 답변을 반환하지 않음.
13. 예측 시 미래 관측값을 과거 시점 학습에 사용하지 않음.
14. 같은 입력 버전과 seed는 동일한 결과를 생성함(솔버 허용오차 이내).

## 12. Codex 최종 실행 지시

> 이 파일을 최상위 제품 요구사항(PRD) 및 인수인계 문서로 간주하고 소프트웨어를 구현하라. **P0의 '사전 인프라 설계' 기능을 최우선**으로 완성하라. 기존 망을 분석하는 대시보드만 만들지 말고, `candidate_asset`에서 **새 연결/증설 시설을 선택하는 최적화**를 반드시 구현하라.
>
> 먼저 실행 가능한 가상 국가-권역 계층 데이터를 생성하고, 정상·장기가뭄·관로파손·복합재난에서 공통으로 사용할 대비망을 예산 제약하에 계산하라. 완성된 공통 설계망에 대해 각 재난별 운영/지역 배분 계획을 제공하라. 지도에는 신설 링크/기존 링크를 시각적으로 구분하고 각 선정 자산의 **선택 이유, 제외했을 때의 결과, 대체 안, 최악 시나리오 피해 감소량 및 자료 불확실성**을 표시하라. 보고서로 저장할 수 있도록 하라.
>
> 계산 엔진에서 생성하지 않은 가짜 성능 수치와 설명은 금지한다. 이후 P1~P3 순서로 확장하라. 이번 단계에서 실제 피지컬 컴퓨팅 제어는 하지 않는다. 실행 방법, 데이터 스키마, 테스트, 남은 제약과 미구현 항목을 문서화하라.
